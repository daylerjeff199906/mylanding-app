    <p>
      La tentación más común en el desarrollo de software moderno es comenzar a programar de inmediato. Construir componentes antes de comprender el dolor real; agregar animaciones antes de tener claridad narrativa; o levantar infraestructuras colosales cuando bastaba simplificar un flujo de dos pasos.
    </p>

    <blockquote class="border-l-2 border-stone-800 dark:border-stone-200 pl-4 py-1 italic font-serif text-lg text-stone-900 dark:text-stone-100">
      "El movimiento debe dirigir la atención. No competir con el contenido."
    </blockquote>

    <h2 class="text-2xl font-serif font-medium text-stone-900 dark:text-stone-100 pt-4">
      Tres reglas de intervención
    </h2>

    <ul class="space-y-2 list-disc pl-5 font-mono text-xs sm:text-sm">
      <li><strong>Observación primero:</strong> Detectar dónde se pierde tiempo, energía o paciencia.</li>
      <li><strong>Descarte activo:</strong> Quitar pasos redundantes antes de intentar automatizarlos.</li>
      <li><strong>Calma operativa:</strong> Crear interfaces que transmitan tranquilidad, no prisa.</li>
    </ul>
